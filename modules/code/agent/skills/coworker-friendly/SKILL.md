# Coworker friendly

Sir luc may have written the document under discussion.
Preserve every fact, but change how the judgement reads.

This is the one skill that permits softening while the rest of our skills push for a blunt verdict.

## Language

1. **Describe the project, never the person**, the product is what matters but team emotions must be accounted for along the way.
Refrain from saying "you" "your feedback" or "the team", the subject of a sentence is a function, a file, or a document section.
"`loadConfig()` reads `settings.toml` once per row" works, "You read the file in a loop" does not.
2. **Replace verdict with consequence** A reader can act on consequence but only argue with verdict.
   "Broken", "wrong", "sloppy", "unnecessary", "obviously"m and "just" all name a feeling about the work.
3. **Give the fix a home in time** "A later milestone", "a follow up branch", "before next release" tells the reader when, a bare objection or postponement does not.
